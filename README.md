# «Чужое алиби» — комплект для Codex, версия 1.0

## Игра — тестовая версия 0.1

Реализован статический браузерный клиент: 8 локаций, событийный движок первого дела, архив, допросы, запросы, свободная доска, ручное сохранение, прокурор и детерминированные финалы. Это ранняя играбельная редакция: иллюстрации пока векторные эскизы, озвучки нет, длительность 60–120 минут ещё не подтверждена плейтестами. Содержание исходного комплекта ниже сохранено как история требований.

### Запуск

Node.js 22.12+ (проверено на 24), npm, Python 3 для проверки контракта.

```sh
npm ci
npm run dev
npm test
python3 tests/validate_case_spec.py
npm run build
npm run preview
```

Если системный npm cache недоступен: `npm ci --cache /tmp/chuzhoe-alibi-npm-cache`.

Браузерные проверки: `PLAYTEST_URL=<адрес работающего локального предпросмотра> npm run test:e2e`. В CI тестовый сервер запускается автоматически. Закрытый Sites требует входа владельца; не отключайте его защиту для тестов.

### Управление

- «Карта» — поездки; двери и список помещений — переходы внутри локации.
- Предмет сначала осматривается. Для получения вещдока нажмите «Изъять в дело» отдельно.
- «Улики» содержит материалы, карточки персонажей и запросы. Ответы забираются лично в участке.
- «Доска» поддерживает drag-and-drop, кнопку добавления из архива, нити через булавки и меню «Соединить с», zoom/pan, клавиатуру и ручные статусы гипотез.
- «Дело» — ручной выбор обвиняемого и приложений. Прокурор консультирует один раз. Окончательная передача необратима.
- Сохранение одно, только ручное. После финала оно недоступно даже после обновления страницы. Настройки находятся в верхней панели.

### Архитектура и размещение

`src/engine` — чистые функции; `src/cases/chuzhoe-alibi` — данные и сценарий; `src/features` — интерфейсы; `src/persistence` — IndexedDB; `public/assets` — оригинальные временные SVG. Авторские summary и truthGuards не попадают в клиентский реестр. Сборка: `dist/`.

Закрытый плейтест: https://chuzhoe-alibi-playtest.tabs718.chatgpt.site — доступ только владельцу через ChatGPT. Идентификатор площадки хранится в `.openai/hosting.json`, секретов в нём нет. GitHub — основной репозиторий; тот же коммит синхронизируется в source repository Sites перед публикацией. Не сохраняйте credentials в файлы или Git.

Подробнее: `docs/architecture-decision-records/0001-stack.md`, `docs/assets.md`, `docs/issues.md`.

## Как начать

1. Распакуйте архив в корень рабочего проекта или в доступную Codex папку `docs/case-chuzhoe-alibi/` (если во втором варианте — укажите Codex реальный путь к документам).
2. Откройте `MASTER_PROMPT.md`, скопируйте его содержимое и отправьте Codex как первое задание. При необходимости добавьте фразу: «Входные файлы находятся в ...».
3. Убедитесь, что Codex **действительно имеет доступ к файлам**; он должен сначала прочитать их, выбрать стек и создать `docs/architecture-decision-records/0001-stack.md`.
4. Начните с вертикального среза, указанного в `DEVELOPMENT_PLAN.md`; затем пройдите все фазы до работоспособного первого дела.
5. После любой правки сценарных триггеров обновляйте `CASE_SPEC.json` и тесты. Проверка структуры без зависимостей: `python tests/validate_case_spec.py`.

## Где заканчивается этот комплект, а где начинается работа Codex

Готово: архитектура **требований**, скрытая истина и временная последовательность, основные сцены/реплики, список улик, детерминированный граф ключевых действий и судебные сочетания, правила навигации и концовок. Предварительные автоматические проверки не выявили логических блокировок в проверенных маршрутах.

Не готово и **не заявляется готовым**: сам браузерный код, реальные иллюстрации и звук, полноценная юридическая редактура суда, все необязательные ответвления реплик и бытовые описания каждой точки локации, продакшн-тестирование 60–120 минут. Это должны быть реальные задачи реализации и авторской вычитки. Стартовый сценарный текст (`DIALOGUES.md`) нельзя принимать за завершенный скрипт всех дополнительных реплик.

## Порядок приоритетов для противоречий

1. **Неизменные решения заказчика**, зафиксированные в `STORY_BIBLE.md` и `GAME_LOGIC.md`: кто виновен, какие алиби правдивы, какие предметы обязательно собирать, какой исход у судов.
2. `GAME_LOGIC.md` — смысл сюжетных ворот и достаточности судебных пакетов.
3. `CASE_SPEC.json` — IDs/формальный контракт и первый набросок машинных правил; если обнаружено расхождение с п. 1–2, исправлять **JSON + тесты**, не первичную историю.
4. `DIALOGUES.md` — текстовый слой; при споре с каноном поправить реплику, не переписывать событие.
5. `GAME_DESIGN.md`, `DEVELOPMENT_PLAN.md` — реализация, UX и процесс.

## Чего нельзя делать при переработке

- Присвоить Норе мотив хладнокровного убийства, заставить Айрин лгать, вывести в дело объективную минуту возвращения Уитмора, объявить Бреннана невиновным сразу после экспертизы ключа.
- Отменить ручное изъятие пуговицы/ключа/пальто или доказать толчок одним совпадением ткани.
- Использовать назначение подозреваемого для сброса открытых комнат или «подмены» старых показаний.
- Выдать окончательную истину в неверном финале.
- Применять к судебному пакету архивные доказательства, которые игрок **не выбрал**.
- Использовать реальные таймеры для готовности запросов, ожидания персонажей или «времени ночи».

## Проверка материалов

```sh
python tests/validate_case_spec.py
```

Она проверяет существование ID, условия типовых действий, достижимость верного финала через разные порядки, возможность проиграть без пуговицы и затем вернуться за ней, исключение первого отчета без ключа, ошибочный вердикт Бреннану и сохранение доступа к комнатам после снятия подозрения. Это не заменяет тесты игрового приложения; Codex должен расширить проверку всего графа, runtime-архива и UI.

## Авторские решения, принятые без дополнительных вопросов

- Осень 1966 года, без точного календарного дня до финальной правовой вычитки.
- Юридический доступ к закрытым помещениям — согласие или оформленное за кадром основание, без самостоятельной механики ордеров.
- Стартовая подача результатов по запросам — через личное получение в участке после именного события готовности.
- Реплики крючков для переходов и недостающие бытовые взаимодействия дописываются в рамках заданного характера и знаний NPC.
- Сложные гипотезы на доске добровольны; обязательна лишь связь для лабораторного сравнения пуговицы и пальто.

## Зачем несколько файлов, а не одно гигантское задание

Codex сможет читать игровую правду отдельно от технического кода, поддерживать проверяемые идентификаторы и писать тесты на развилки, не переписывая художественный текст при каждом рефакторинге. Для второго дела потребуется новый набор данных (`caseId`), а не новая копия всего приложения.
