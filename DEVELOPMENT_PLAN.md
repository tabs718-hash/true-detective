# «Чужое алиби» — план реализации и приемки для Codex

Версия 1.0. Основная цель — **завершенная играбельная версия первого дела**, не бесконечный прототип и не только дизайн-макет. Разработка идет в существующем локальном Git-репозитории или в новом репозитории, если его еще нет. Пользователь самостоятельно связывает нужные GitHub-учетные данные и предоставляет доступ; не предполагать, что он уже настроен.

## Фаза 0 — проверка среды и выбор стека

1. Осмотреть репозиторий, README, package manifest, существующий код, лицензию и средства запуска.
2. Если проект пустой, предложить/зафиксировать обоснованный стек **самим Codex** с учетом однопользовательского браузера без обязательного сервера, JSON/TypeScript-данных, надежного state machine, удобного тестирования на desktop, свободной доски с панорамированием и анимаций без тяжелого видеорендера. Не навязывать стек из промпта заранее.
3. Создать `docs/architecture-decision-records/0001-stack.md` с аргументами, ограничениями, сценариями отказа от альтернатив. Разработчик вправе выбрать легкие библиотеки, если они сокращают сложность и не ухудшают поддержку.
4. Проверить точные команды сборки/запуска/тестов и доступные версии инструментов.
5. Сформировать карту ассетов и лицензий, выделить отсутствующие изображения/аудио как production TODO с честными заглушками.

**Приемка:** проект запускается одной задокументированной командой; сборка проходит; ADR описывает стек и архитектуру; нет хардкода ключевых фактов в UI.

## Фаза 1 — слои данных и движок событий

- Реализовать типизированный реестр `Location`, `Room`, `Hotspot`, `EvidenceCard`, `DocumentCard`, `WitnessStatement`, `ForensicReport`, `Topic`, `DialogueNode`, `Action`, `Condition`, `Request`, `BoardLink`, `CasePacket`, `Verdict`.
- Вся логика проверки триггеров — чистые функции с предсказуемым результатом, без времени/рандома.
- Состояние `facts` монотонное, `suspects` редактируемое, `openedRooms` монотонное; инварианты в DEV tests.
- Запросы как state-machine `not_submitted → pending → ready → collected`, где `ready` определяется событиями, не таймером.
- Разделить `observedObjects` и `collectedCards`; два действия на один хотспот; запрет дублирования карт.
- Все герои доступны для ручной отметки подозреваемого, даже когда не разработано специального контента.
- Заложить структуру расширения будущих независимых дел с отдельными наборами идентификаторов, не связывая логику первого дела с корневой игрой.

**Приемка:** юнит-тесты для триггеров и инвариантов, машина сценария может пройти без браузера.

## Фаза 2 — вертикальный срез 10–15 минут

Реализовать киноинтро с пропуском, стройку (включая **отдельные действия «Осмотреть» и «Изъять» для ключа и пуговицы**), приемную с Норой, Оуэна, первый допрос Бреннана, архив, журнал, карту, одну ручную ячейку сейва. Макеты временные, но стилистически согласованные. Можно завершить этот вертикальный срез без суда.

**Приемка:** игрок может пропустить интро, изъять/не изъять предметы, уйти и вернуться, изучить архив, вызвать Бреннана, сохранить/перезагрузить игру; состояние не повреждено.

## Фаза 3 — полная середина расследования

Сделать особняк и его первую сцену, АЗС, Хейза I, бухгалтерию (открыта только после Бреннана), рабочий кабинет, счета и незаметную ведомость Marlowe, Дэниела I, финансовые запросы с получением результатов в участке, тайную съемную квартиру и признание романа, Айрин в участке, повторную Элизабет и ее ограниченное отсутствие алиби.

**Приемка:** обе ветви — Бреннан/Элизабет и бухгалтерия/Дэниел — играбельны в разном порядке, могут сходиться без необходимости соединять карточки на доске. Дэниел **не появляется раньше счетов**.

## Фаза 4 — медики, поздние сцены, логика победы

- Первый отчет по ключу строго после физического изъятия и сюжетной готовности; ключ исключается как орудие.
- Отдельный доп. меданализ по сценическим фото и вскрытию, после романа, без повторного посещения объекта; отсроченная смерть, не точное время.
- Хейз II отдельно после романа и одной из двух дополнительных вех; Эдди уже в участке и весь рассказ в одном допросе.
- Дополнительная карточка эксперта о совместимости позднего дыхания с отсроченной смертью — после двух исходных карт в любом порядке.
- Домашний кабинет открывается с согласия Элизабет по утвержденным условиям; личные бумаги в двух местах; подозрение Норы, квартира Норы и пальто.
- Нора: серьезный допрос допускается до совпадения пуговицы; результат засчитывается впредь.
- Доска с двумя способами добавить, двумя способами связать, версионными гипотезами; **только нить пуговица+пальто** включает лабораторное сравнение.

**Приемка:** все golden paths и противоположные порядки событий; при пропущенном ключе можно закончить дело, но первый отчет недоступен; при пропущенной пуговице обвинить Нору можно, победить — нет.

## Фаза 5 — суд, консультация и концовки

Один поход к прокурору в отдельную локацию, только выбранные карты. Сбор выбранного пакета с полями и необратимым подтверждением. Неправильный приговор Бреннану при строго заданных условиях, оправдание Элизабет, недоказанность Норы без экспертной связи, отказ по Дэниелу/Эдди/Хейзу, общий пустой пакет. Только правильный финал открывает флешбэк истины. После финала — начать заново, нельзя загрузить старый сейв. Счетчик только реально найденных уникальных карточек.

**Приемка:** `verdictEngine` unit tests для каждого outcome, проверка «секрет Норы никогда не утек в плохой финал» на всех русских строках/аудио/иллюстрациях.

## Фаза 6 — авторское наполнение и полировка

- Полностью дописать на основе DIALOGUES.md вторичные диалоги, альтернативные ответы, журналистику расследования, описания всех хотспотов и документы в виде коротких карт.
- Пересмотреть все тексты на внутреннюю причинность и знания каждого персонажа; проверить русскую грамматику.
- Подготовить одинаково стилизованные арт-ассеты, звуковую палитру и портретные эмоции; избегать несовместимой исторической атрибутики.
- Подготовить исполняемый прогон для новичка и опытного игрока в рамках заявленных 60–120 минут, отслеживая только длительность тестирования (в игре таймера нет).
- Проверить доступность с клавиатуры, контраст, субтитры, скорость появления реплик, управление zoom/pan доски.

**Приемка:** русскоязычное дело полностью проходимо, не содержит заглушек вида `[TODO: текст]` в релизной сборке, ключевой визуальный стиль согласован; отсутствующие негенерируемые ассеты перечислены как открытое внешнее требование, а не молча заменены чужими нелицензированными материалами.

## Фаза 7 — контроль качества, публикация, расширение

Автоматизированные тесты: чистые unit для состояния/условий/суда, интеграционные по сюжетным маршрутам, E2E через браузер (desktop), перезагрузка на разных этапах, восстановление одного сейва, полные и пустые пакеты, перезапуск после финала. Проверить сценарий повторного захода в кабинет и корректную отдельность квартиры Норы/тайной квартиры. Проверка console errors, отсутствия network requests к неподтвержденным сервисам и доступности в offline/slow network при статической публикации. Настроить build, smoke test и развертывание на целевой хостинг после получения сведений от пользователя, без выдуманных учетных данных. Для каждого следующего дела — новый `caseId` и отдельный реестр сцен, карт, концовок.

## Требования к GitHub-процессу

- Не `git push --force`, не удалять пользовательские файлы без причины.
- Маленькие коммиты по логическим фазам; описательные сообщения; не хранить токены и конфигурацию хостинга в репозитории.
- README с командами install/dev/test/build/preview, скриншоты или краткие видео ключевых сцен при наличии средств.
- CI: сборка, lint, форматирование, tests, проверка структуры `CASE_SPEC.json`.
- После этапа — короткий отчет: что реализовано, команды проверок и результаты, открытые проблемы, следующий технически оправданный этап.

## Матрица приемки (минимальная)

| Проверка | Ожидаемо |
|---|---|
| Пуговица только осмотрена | Нет карточки E_BUTTON, есть запись журнала, повторный осмотр возможен |
| Ключ не изъят | R_WRENCH никогда не появляется |
| Счета не найдены | Дэниел лично не появляется |
| Бухгалтерия до допроса Бреннана | Вход закрыт |
| Роман раскрыт без доп. меданализа | Хейз II доступен через Элизабет, затем Эдди и дом. кабинет |
| Доп. меданализ раньше Эдди | Домашний кабинет доступен, экспертное уточнение — после Эдди |
| Заявление Эдди раньше меданализа | После меданализа экспертное уточнение доступно без нового Эдди |
| Элизабет снята с подозрения | Ранее открытые комнаты не закрываются |
| Нора допрошена до экспертизы пуговицы | Победа позже возможна без повторного допроса |
| Нора без R_BUTTON_MATCH в пакете | Оправдание, не раскрывать убийцу |
| Бреннан + R_WRENCH в пакете | Нет ошибочного осуждения с ключом как орудием |
| Прокурор вызван один раз | Второй вызов недоступен |
| Передача дела подтверждена | Невозможно загрузить текущую партию |
| Финальный отчет | Только число найденных уникальных улик, без общего количества |

## Готовность релиза

«Готово» означает: существует собранный клиент, все обязательные ветви воспроизводятся без чтения кода, диалоги и судебные результаты не противоречат STORY_BIBLE.md, тесты охватывают граф состояний, настройки работают, README позволяет самостоятельно запустить и опубликовать игру. Не принимать «страницы выглядят красиво» за завершение задачи без рабочих расследований и суда.
